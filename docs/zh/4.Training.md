# 4. 训练 DeepH 模型

本部分给出 DeepH 训练的快速示例。

**注意：** 本章的操作应在 `deeph` uv 环境下进行。

为便于演示，我们附带了三个不同的示例数据集：$\text{H}_2\text{O}$（[FHI-aims](https://fhi-aims.org/)）、
石墨烯（[ABACUS](https://abacus.deepmodeling.com/en/latest/)）和 $\text{Mo}\text{Te}_2$
（[OpenMX](https://www.openmx-square.org/)）。请注意，受数据体量限制，这里只提供了训练数据集的一小部分
子集，不足以完成多数实际训练任务。推理部分我们使用的是在一个足够大的数据集上充分收敛的预训练模型，
并据此可视化 DeepH 推理得到的能带结构。

请不要把涉及的三个数据集搞混。对应的训练配置文件分别位于 H2O
（`~/workshop/4.Training/H2O_5K_FHI-aims`）、石墨烯（`~/workshop/4.Training/Graphene_500_ABACUS`）和
MoTe2（`~/workshop/4.Training/MoS2_500_OpenMX`）目录下。你也可以通过各配置文件（`*.toml`）中的
`dataset_name` 字段来区分它们。不过，由于 DeepH 在设计上就能无缝处理分子体系和固体体系，这些示例的
配置文件大体上是相似的。


## 4.1. 构建训练数据的图文件

DeepH 模型是图神经网络（GNN）。它以原子结构为输入，预测物理量。输入的结构被当作以原子为节点的图：
任意一对原子 $i$ 和 $j$，如果距离足够近（即二者的原子轨道基函数有重叠），就由有向边 $i \rightarrow j$
和 $j \rightarrow i$ 相连；图中还存在自环 $i \rightarrow i$。哈密顿量矩阵元这类物理量，则被解释为与图的
节点和边相关联的*特征*。

在实现上，图文件直接由 DFT 数据构建，与 DeepH 的训练过程在数据上完全等价。相比于传统的、基于目录分散
存放 DFT 数据的方式，图文件体系有多方面技术优势：

- **数值精度可配置：** DeepH-pack 支持用户自定义 32 位或 64 位浮点精度来存储，通过优化数据类型配置显著
  提升存储效率。
- **数据便于搬运：** 借助单文件集成的结构，在跨服务器集群传输时，图文件应当优先于原始碎片化数据使用，
  以简化数据迁移。
- **通用兼容性：** 图文件格式采用通用数据结构设计，不仅与 DeepH 框架兼容，理论上也可扩展到其他神经网络
  架构的训练流程中。

在 DeepH-pack 中，图文件夹的布局如下：

```bash
graph/
  |- <GRAPH_NAME>.<GRAPH_TYPE>.memory.pt
  |- <GRAPH_NAME>.<GRAPH_TYPE>.disk.pt
  |- <GRAPH_NAME>.<GRAPH_TYPE>.disk.part1-of-1.db/
  |- <GRAPH_NAME>.<GRAPH_TYPE>.disk.part1-of-1.info.pt
```

原始 DFT 数据的根目录必须命名为 `graph/`，所有图文件都存放在该目录下。

DeepH-pack 目前支持两种图文件存储模式：

  - `memory` 模式。在 DeepH 训练初始化时把整个图文件预加载进节点内存，对于内存装得下的数据集优先保证
    运行效率。
  - `disk` 模式。借助数据库与硬件集成的存储方案按需流式读取，专门面向超出节点内存容量的超大图文件
    （例如 >10 TiB）。

这种双模式架构通过动态适配数据规模，实现了与内存无关的训练流程：disk 模式在计算过程中实时访问数据，
同时避免占满内存，从而在各类计算资源约束下都保持系统灵活性。

要启动 DeepH 训练：

- 既可以准备好 DFT 目录（训练开始时自动构建图）；
- 也可以直接提供预先构建好的图文件（从外部传输到 GPU 集群）。

两种方式 DeepH-pack 都完全支持。

```bash
inputs/
  |- dft/                # DFT data folder (optional, if graph folder exist)
    |- <sid>               # Structure ID
       |- info.json        # Additional information
       |- POSCAR           # Atomic structures
       |- overlap.h5       # Overlap matrices of basis in {R}
       |- (hamiltonian.h5) # Hamiltonian entries in {R}
       |- (position.h5)
       |- (charge_density.h5)
       |- (density_matrix.h5)
       |- (force.h5)
    |- ...
  |- graph               # Graph folder (optional)
    |- <GRAPH_NAME>.<GRAPH_TYPE>.memory.pt
    |- <GRAPH_NAME>.<GRAPH_TYPE>.disk.pt
    |- <GRAPH_NAME>.<GRAPH_TYPE>.disk.part1-of-1.db/
    |- <GRAPH_NAME>.<GRAPH_TYPE>.disk.part1-of-1.info.pt

```


## 4.2. 单独构建图

启动一次标准的 DeepH 训练时，框架会自动从指定 `dft/` 目录下的 DFT 数据构建图文件，并生成相应的图
`dataloader`。鉴于图构建完全在 CPU 上完成，而图文件在数据搬运上又有天然优势，DeepH-pack 同样支持把
图构建与 GPU 加速的训练过程解耦。如果图文件已经存在，训练会跳过原始 DFT 数据，通过这种基于图的数据
抽象来简化训练流程。

`build_graph.toml`：
```toml
# ----------------------------- SYSTEM -----------------------------
[system]
note = "Welcome to DeepH-pack!"
device = "cpu"
float_type = "fp32" # or `fp64`
random_seed = 137

# ----------------------------- DATA -------------------------------
[data]
inputs_dir = "."          # Inputs path that contains `dft` and `graph`
outputs_dir = "./logs"    # Logging path

[data.graph]
dataset_name = "H2O_5K"
graph_type = "HS"         # Graph will include both Hamiltonian and Overlap matrices
storage_type = "memory"   # Or `disk`
parallel_num = -1         # Parallel processes during build graph
only_save_graph = true    # A task for generate and save graph only
```

之后就可以用下面的命令构建数据图文件：

``` bash
deeph-train build_graph.toml
```

**注意：** 对于 `only_save_graph` 任务不需要 GPU。请按第 2 章所述，在 CPU 版依赖下安装 DeepH-pack。
```bash
uv pip install ./deepx-1.0.6+light-py3-none-any.whl[cpu] --extra-index-url https://download.pytorch.org/whl/cpu
```

## 4.4. 在 FHI-aims 处理的 H2O-5k 分子数据集上训练 DeepH 模型

在 `inputs/` 目录下准备好训练数据后：

- 创建一个最小的 TOML 配置文件 `train.toml`
- 对于本地 GPU 工作站，执行以下命令：
```bash
cd ~/workshop/4.Training/H2O_5K_FHI-aims
deeph-train train.toml
```

- 对于高性能计算集群（当前配置便是如此），准备一个作业提交脚本，
```bash
#!/bin/bash
#
#SBATCH --job-name=H2O-5k-FHI-aims
#SBATCH --gpus=1
#SBATCH -p gpu

module load cuda/12.9               # Load CUDA
source ~/.uvenv/deeph/bin/activate  # Load DeepH venv

deeph-train train.toml
```
然后提交作业，
```bash
sbatch submit.sh
```

---

TOML 配置文件包含四个核心部分：

- `system`：负责硬件与计算环境等声明。
- `data`：指定训练数据集的位置、特征与元数据等。
- `model`：定义基础架构组件与目标物理量（不限于哈密顿量——未来的版本会逐步支持力场、原子间势、电荷密度、
  密度矩阵、GW 计算等），包括损失函数的选择。
- `process`：通过收敛判据、数据加载器配置、优化器、重启设置等来控制训练/推理流程。

受篇幅与时间所限，本节无法穷尽所有 TOML 配置细节，下面只给出当前模型最关键的参数。更多内容请参阅
*用户手册*。

- `system.device`：设备配置遵循 `<type>*<num>:<id>` 语法，其中 `<type>` 指定硬件类型（`cpu`、`gpu`、
  `tpu`、`rocm`、`dcu` 或 `cuda`），`<num>` 表示每节点的设备总数（对 GPU 之类的加速卡而言）或 CPU 分区的
  数量（使用 `cpu` 时），`<id>` 指定目标设备编号（例如 `gpu*8:1-4,7` 表示在 8 卡节点上按编号
  1,2,3,4,7 选用 5 张 GPU，`gpu*3` 表示 3 卡节点上的全部 GPU）。**注意**，对于 CPU 配置，`<id>` 会被忽略，
  由 `<num>` 控制线程划分。

- `model.net_type`：神经网络架构。在 DeepH-pack Light 版本中有两种架构可选：
  - `sparrow` 是一种轻量架构（通常参数量 <1M），同时使用节点与边的特征，适合 DFT 哈密顿量学习中的
    小型任务。（类似 DeepH-E3 的网络）
  - `eagle` 是一种进阶架构（参数量典型值 $\sim$ 5M），同时使用节点与边的特征，适合对精度要求较高的
    DFT 哈密顿量学习任务。

- `model.advanced.net_irreps`：神经网络特征的不可约表示，用来保证网络的等变性。以
  [`e3nn.Irreps`](https://e3nn-jax.readthedocs.io/en/latest/api/irreps.html) 的字符串形式设置，即
  *不可约表示*，描述输入特征的对称性。**注意**，对于哈密顿量预测任务，`Irreps` 中指定的最大 $l$ 至少要达到
  哈密顿量基组中最高角动量量子数的两倍。这一要求来自 Irreps 要把哈密顿量的非耦合表示（直积基）变换为
  耦合表示（直和基）。例如，当基组包含 f 轨道（$l=3$）时，Irreps 必须支持 $l_{\text{max}} \geq 6$。

- `process.train.optimizer.init_learning_rate`：初始学习率。

- `process.train.scheduler.min_learning_rate_scale`：学习率的最小缩放系数。当学习率的乘数降到该阈值时，
  训练会自动终止，此时的有效学习率为 `scale` $\times$ `initial_learning_rate`。

完整的 GPU 训练配置文件如下：

```toml
# ---------------------------------- SYSTEM ----------------------------------
[system]
note = "DeepH-JAX"
device = "gpu*1"
float_type = "fp32"
random_seed = 137
log_level = "info"
jax_memory_preallocate = true
show_train_process_bar = false

# ----------------------------------- DATA ------------------------------------
[data]
inputs_dir = "./inputs"
outputs_dir = "./outputs"

[data.dft]
data_dir_depth = 0
validation_check = false

[data.graph]
dataset_name = "H2O_5K"
graph_type = "HS"
storage_type = "memory"
common_orbital_types = ""
parallel_num = -1
only_save_graph = false

[data.model_save]
best = true
latest = true
latest_interval = 1
latest_num = 10

# ----------------------------- MODEL -----------------------------------------
[model]
net_type = "eagle"
target_type = "H"
loss_type = "mae"

[model.advanced]
gaussian_basis_rmax = 10.0
net_irreps = "64x0e+48x1e+32x2e+16x3e+8x4e+8x5e+4x6e"
num_blocks = 3
num_heads = 2
enable_bs3b_layer = false
bs3b_orbital_types = ""
consider_parity = false
standardize_gauge = false

# ------------------------------ PROCESS --------------------------------------
[process.train]
max_epoch = 10000

multi_way_jit_num = 1
ahead_of_time_compile = true
do_remat = false

[process.train.dataloader]
batch_size = 100

train_size = 3000
validate_size = 1000
test_size = 999
dateset_split_json = ""
only_use_train_loss = false

[process.train.drop]
dropout_rate = 0.0
stochastic_depth = 0.0
proj_rate = 0.0

[process.train.optimizer]
type = "adamw"
init_learning_rate = 1E-3
clip_norm_factor = -1.0
betas = [0.9, 0.999]
weight = 0.001
eps = 1E-8

[process.train.scheduler]
min_learning_rate_scale = 1E-5
type = "reduce_on_plateau"
factor = 0.5
patience = 500
rtol = 0.05
cooldown = 120
accum_size = -1

[process.train.continued]
enable = false
new_training_data = false
new_optimizer = false
previous_output_dir = ""
load_model_type = "latest"
load_model_epoch = -1
```

**注意：**

- 在 `process.train.dataloader` 配置中，`train_size`、`validation_size` 与 `test_size` 三者之和不得超过
  数据集中的结构总数。违反该约束会抛出 `ValueError()` 异常。
- 目前 DeepH *尚不*支持跨节点的 CPU 推理，该功能将在后续版本中实现。

```bash
outputs/<timestamp>
  |- dataset_split.json
  |- deepx.log          # <-- DeepH logging file
  |- model/
      |- train.toml     # <-- Copy of training settings
      |- variables.json # <-- Model.__init__(variables)
      |- params/        # <-- Model parameters store here
        |- best.pytree
            |- epoch_124/
        |- latest.pytree
            |- epoch_120/
            |- epoch_110/
            |- epoch_100/
            |- ...
      |- states/        # <-- Optimizer states store here
        |- best.pytree
        |- latest.pytree
```

## 4.7. 在 OpenMX 处理的 MoS2-500 数据集上训练

本示例中我们改用基于磁盘的图构建模式来训练模型。与此前示例所用的内存模式相比，磁盘模式有两个关键优势：

1. 降低内存占用（按需从数据库加载）
2. 减少磁盘空间消耗（采用 zlib 压缩）

不过这一做法也带来一个明显的取舍：受服务器磁盘 I/O 限制（尤其在 NFS 之类的网络存储上），图加载速度会
大幅下降，可能慢一到两个数量级。

要从基于内存的图构建切换到基于磁盘的方式，只需修改配置参数：
```python
data.graph.storage_type = "disk"
```
然后照常执行训练任务即可。

```bash
cd ~/workshop/4.Training/MoS2_500_OpenMX
sbatch submit.sh
```
