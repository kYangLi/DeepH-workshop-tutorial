# 3. 为 DeepH 准备 DFT 数据

本部分展示如何通过 DFT 接口生成数据集。

**注意：** 本章的操作应在 `deeph` uv 环境下进行。

## 3.1 用 DeepH-dock 对接 DeepH

DeepH-dock 提供了多种接口来准备 DeepH 所需的数据集。目前支持的软件包包括 OpenMX、SIESTA、
ABACUS、FHI-aims 和 HONPAS。DeepH 团队衷心感谢这些 DFT 软件开发团队的支持。

### 3.1.1 DeepH 格式文件概览

出于 I/O 效率的考虑，新版 DeepH 用一套新格式优化了数据集的存储结构。从旧版格式到当前 DeepH 版本的
格式转换请参见 3.2.1 节。

DeepH 格式数据集的目录树结构大致如下：

```bash
dft/ # DeepH-ready data
  |- label-0/
     |- POSCAR
     |- info.json
     |- overlap.h5
     |- hamiltonian.h5
  |- label-1/
  |- ...
```

其中 `overlap.h5`、`hamiltonian.h5` 是局域原子轨道（AO）基组下对应的矩阵，`POSCAR` 文件包含结构
信息，`info.json` 文件则保存该结构的关键元数据。根目录名 `dft/` 是与现代 DeepH 工具链兼容所必需的，
而各个样本子目录的命名则可以按项目习惯来定（数字索引、化学原型等）。旧版与新布局之间的转换在 3.2 节讨论。

### 3.1.2 OpenMX 接口
OpenMX（Open source package for Material eXplorer）是一个开源的 DFT 计算软件包，基于模守恒赝势和
赝原子轨道基组，用于纳米尺度的材料模拟。

要从 OpenMX 计算中得到 DeepH-pack 所需的原始数据（哈密顿量、重叠矩阵等），需要在 OpenMX 的输入文件
`*.in` 中加入选项：

```
HS.fileout ON
```

计算完成后，最终结构与物理性质保存在 `*.scfout` 文件中。

OpenMX 计算的目录结构应当组织为：

```bash
openmx_calculations/ # openmx raw data
  |- label-0/
  |- label-1/
  |- ...
```

然后用下面的命令把原始数据转换为 DeepH-pack 格式：

```bash
dock.io.OpenMXToDeepH --openmx ./openmx_calculations --deeph ./dft -p 1
```

转换完成后的目录树应当如下：

```bash
openmx_calculations/ # openmx raw data
  |- label-0/
  |- label-1/
  |- ...
dft/ # converted data
  |- label-0/
     |- POSCAR
     |- info.json
     |- overlap.h5
     |- hamiltonian.h5
  |- label-1/
  |- ...
```

### 3.1.3 SIESTA 接口
SIESTA 既是一种方法，也是该方法的具体程序实现，用于在严格局域的原子轨道基组下做高效的电子结构计算。

要从 SIESTA 计算中得到 DeepH-pack 所需的原始数据，需要在 SIESTA 输入文件 `*.fdf` 中加入选项：

```
SaveHS .true.
```

计算完成后，最终结构保存在 `*.XV` 文件中，物理性质保存在 `*.HSX`、`*.DM` 等文件中。

SIESTA 计算的目录结构应当组织为：

```bash
siesta_calculations/ # siesta raw data
  |- label-0/
  |- label-1/
  |- ...
```

然后用下面的命令把原始数据转换为 DeepH-pack 格式：

```bash
dock.io.SIESTAToDeepH --siesta ./siesta_calculations --deeph ./dft -p 1
```

转换完成后的目录树应当如下：

```bash
siesta_calculations/ # siesta raw data
  |- label-0/
  |- label-1/
  |- ...
dft/ # converted data
  |- label-0/
     |- POSCAR
     |- info.json
     |- overlap.h5
     |- hamiltonian.h5
  |- label-1/
  |- ...
```

需要注意，SIESTA 允许对同一元素的原子使用不同的设置（例如体相硅与表面硅使用不同的基组和赝势），但
DeepH-pack 无法区分这些差异，会把它们当作同一种元素处理。为避免这个问题，请不要在 `ChemicalSpeciesLabel`
块中对同一元素使用多套设置（例如不要同时出现 "1 14 Si1" 和 "2 14 Si2"）。

### 3.1.4 ABACUS 接口
ABACUS（Atomic-orbital Based Ab-initio Computation at USTC）是一个开源软件包，面向大规模第一性原理
电子结构模拟。ABACUS 同时支持平面波基组和原子轨道基组，而 DeepH-dock 只实现了原子轨道基组模式下的接口。

要从 ABACUS 计算中得到 DeepH-pack 所需的原始数据，需要在 ABACUS 输入文件 `INPUT` 中加入选项：

```
basis_type lcao
out_mat_hs2 1
```

计算完成后，最终结构保存在 `running_*.log` 文件中，物理性质保存在 `data-*.csr` 文件中，这些文件都
输出在 `OUT.*` 目录下。

ABACUS 计算的目录结构应当组织为：

```bash
abacus_calculations/ # abacus raw data
  |- label-0/
  |- label-1/
  |- ...
```

然后用下面的命令把原始数据转换为 DeepH-pack 格式：

```bash
dock.io.AbacusToDeepH  --abacus ./abacus_calculations --deeph ./dft -p 1
```

转换完成后的目录树如下：

```bash
abacus_calculations/ # abacus raw data
  |- label-0/
  |- label-1/
  |- ...
dft/ # converted data
  |- label-0/
     |- POSCAR
     |- info.json
     |- overlap.h5
     |- hamiltonian.h5
  |- label-1/
  |- ...
```

需要注意，ABACUS 与 SIESTA 一样允许对同一元素的原子使用不同设置。为避免这个问题，`ATOMIC_SPECIES`
块中的元素标签应使用标准元素符号，而不是用户自定义符号（例如硅原子只允许写 Si，不允许写 "Si1"）。

当前接口是针对 ABACUS 3.10LTS（长期支持版本）开发的，其他版本输出的文件名与 LTS 版本不同。

## 3.2 用旧版接口对接 DeepH

值得注意的是，重构后的 DeepH-pack 当前版本配套了一套更紧凑的数据格式（称为 `DeepH` 格式），与之相对
的是旧格式（称为 `DeepH-legacy` 格式）。两种格式包含的信息相同，而 `deeph-dock` 中提供了把
`DeepH-legacy` 转换为 `DeepH` 的数据转换接口。这个转换是有意义的，因为：
1. 现有的 DeepH 用户手上有大量旧格式数据集；
2. 目前仍有若干接口直接输出旧格式的数据。

#### 3.2.1 用 DeepH-dock 做数据转换

装好 DeepH-dock 后，数据转换非常简单，只需一条命令：

```bash
dock.io.DeepHOldToNew -p [PARALLEL_NUM] <legacy_dir> <updated_dir>
```

例如：

```bash
dock.io.DeepHOldToNew -p 1 ./collect_preprocessed ./dft
```

转换后的数据会保存在 `<updated_dir>` 中。

新格式的数据也可以用下面的命令反向转回旧格式，以便与基于旧格式的工具交互：

```bash
dock.io.DeepHOldToNew -p [PARALLEL_NUM] --backward <legacy_dir> <updated_dir> 
```

注意，即使在反向转换时，新格式目录仍然放在命令的后面。

#### 3.2.2 与旧版 DeepH 格式对接的接口
与旧版 DeepH 格式对接的接口包括：
1. [DeepH@FHI-aims 接口](https://deeph-fhi-aims-interface-3c4d14.gitlab.io/)
2. [DeepH@HONPAS 接口](https://zenodo.org/records/14979348)
3. 其他支持旧版 DeepH 的接口，例如 [DeepH-pack 在 GitHub 上的开源接口](https://github.com/mzjb/DeepH-pack)。

使用这些接口准备好数据集后，还需要经过 3.2.1 节提到的额外数据格式转换。

## 3.3 数据集生成的指导与注意事项

#### 3.3.1 数据集里应该包含什么？
需要说明的是，为 DeepH 训练生成数据集在很大程度上是一个开放问题，强烈依赖于你打算研究什么。下面针对
几种简单情形给出参考建议：

1. **扰动数据集**的生成。在扰动数据集上训练 DeepH，对于研究
   [电声耦合](https://journals.aps.org/prl/abstract/10.1103/PhysRevLett.132.096401) 之类的应用很有用。
   数据集既可以由随机扰动生成，也可以来自从头算分子动力学。在我们的示例研究中，两种方式都训练过 DeepH。
2. **莫尔扭转材料**的数据集生成。DeepH 有能力从小尺寸结构的哈密顿量中学习，并推广到大尺寸结构，例如从
   非扭转的小尺寸双层推广到大规模莫尔扭转体系。由于存在扭转，莫尔超胞中会出现不同的局域堆垛方式（如 AA、
   AB 和 BA）。因此训练集可以通过加入含**随机层间平移**以及随机原子扰动的结构来构建。
3. **更复杂结构**的数据集生成。基于数据库结构来考察 DeepH 在现有数据库上的表现，对于建立
   [**通用 DeepH 模型**](https://www.sciencedirect.com/science/article/pii/S2095927324004079) 是很有意义的。
   用 DeepH 考察**缺陷/界面/合金**的电子结构同样很有价值。若需要生成结构，我们推荐使用可以与
   DeepH@FHI-aims 接口无缝衔接的专用结构生成软件包。

#### 3.3.2 关于数据集的重要提示
以下几条经验法则对数据集生成可能有帮助：

1. **数据集体量**：对于扰动结构或莫尔扭转材料，DeepH 通常需要 50 到 500 个结构，具体取决于材料的复杂度和
   你所施加扰动的幅度。我们仍建议用户针对自己的场景检查数据是否充足。
2. **粗略的精度估计**：DeepH 模型"准确"的一个大致数量级是哈密顿量的平均绝对误差（MAE）小于 1 meV。
   但在多数数据集上，你会发现 DeepH 的精度远好于此。
3. **反复检查数据可靠性**：生成数据集时请务必避免纳入荒谬的结构，例如原子间距过近的结构，或未收敛的结构。
   哪怕只混入一个这样的结构，也可能对训练造成灾难性影响。
4. **保证数据质量**：建议使用充分收敛的 DFT 参数来生成数据集，包括实空间格点截断、k 网格采样、SCF 收敛
   判据等。参数收敛不佳时，数据集看起来就像是由随机"噪声"组成的，会给 DeepH 的训练带来很大困难。
5. **避免使用过大的基组**：由于预测的哈密顿量是在非正交基组下表示的，基组过大时，哈密顿量的后处理容易
   病态，并因基组的近线性相关而带来较大的数值误差。
6. **避免使用高角动量基组**：对 DeepH 而言，处理对应高角动量基组的哈密顿量矩阵元非常耗时，因此在实际使用
   中建议基组最高只用到 *f* 轨道。另外，如果你使用的基组最高到 $l_{\text{max}}$，那么 DeepH 的不可约表示
   至少要支持到 $2l_{\text{max}}$，这一点将在第 4 章说明。
